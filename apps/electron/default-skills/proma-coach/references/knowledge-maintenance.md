# 长期协作知识

目标是减少重复沟通、探索和错误。主动从当前对话和已有可靠证据识别有助于未来协作的用户核心事实，及时维护 Profile；用户的明确纠正优先更新。项目经验和决策按相关主题维护，完成后简要说明实际写入。用户禁止记忆写入、只读或计划模式时不写；不从单次行为推断画像，不存凭据，不主动收集敏感个人信息。

## 必需结构与作用范围

- 全局 `user_profile.md` 始终注入，最多 100 条、5000 字符；每条一条核心事实，一句简短陈述，只保留必要的范围和来源。合并重复，不写故事、推理或任务过程，不为填满预算增加事实。超限时，可写用户主会话主动调用 `collaboration.start_profile_maintenance`，把本次未保存的已确认事实及依据交给专用后台子会话；无需等待即可继续独立主任务，启动不代表完成。若已有整理在运行，本次事实未被接收，须保留并在整理结束后重新读取、更新和核验。后台子会话完整读取画像，语义去重并整理至约 4000–4500 字符，使用最新 revision 更新并回读；保留历史及必要来源，确实无法安全整理时保留原文并说明阻塞。只读、计划模式、禁止记忆写入、自动化和其他子会话不得主动启动后台整理。不创建 Profile 子目录或链接。项目 `memory/MEMORY.md` 保存主题路由。
- 项目 `AGENTS.md` 必须有「记忆维护」方案并链接项目索引和全局画像。可写项目任务中缺少结构时调用 `MemoryInitialize`，允许写明「暂无已确认事实」，不编造、不要求填写问卷。
- 项目专属偏好写入 `project-preferences.md` 并加入索引。发现 Profile 与项目记忆重叠时，确认所属项目和授权，先核对并补齐项目记录，再整理 Profile；归属不明或不可写时保留原文。
- 项目约定、架构、命令属于 `AGENTS.md`；长调研与项目证据属于项目 Context；当前任务进度属于工作台；可复用执行流程才属于 Skill。已配置且授权访问的 Obsidian Vault 用于长期领域知识：结合当前任务主动补充有复用价值的知识，先查找并完善已有主题笔记，保留来源和双链；不逐轮归档、不自动建库或切库。Vault 未启用或不可访问时不擅自配置，沿用项目记忆与 Context。

## 从多个项目合并旧画像

运行时发现已登记工作区的 `memory/` 或旧 `.claude/memory/` 下的 `user_profile.md` / `user-profile.md` 时会提示。在允许写入的用户项目会话收尾前集中逐份迁移，无需等待用户点击「整合画像」或专门提出要求；用户要求只读、禁止记忆写入或停止时不执行，计划模式、自动化和委派不自行发起跨项目迁移。项目 AGENTS.md 首次维护完成与全局画像整合是独立状态，前者完成不阻止后者。用户点击「整合画像」时直接处理全部待整合来源，并优先恢复中断记录。旧画像不会作为当前全局事实自动注入。

1. 用 `MemoryInspect` 获取来源列表，再按 `sourceId` 读取源画像、全局画像、源项目的索引和偏好及所有版本。不要拿当前项目偏好替换源项目偏好。
2. 按条目语义合并：相同事实去重，互补事实合并；跨项目稳定偏好归全局，项目特例归源项目偏好。保留来源项目、原文件和实际依据日期。新文件时间不代表事实更可靠。用户明确纠正可以取代旧事实；未解决的冲突保留范围和来源并标为待确认，必要时询问，不能选一个覆盖另一个。
3. 准备完整的新全局正文、源项目偏好及索引，保留无关内容。源索引移除本次旧画像入口；项目偏好有内容时添加 `project-preferences.md`。其他仍待迁移的画像入口先保留。源索引与当前存储目录索引为同一文件时，两份内容应相同。
4. 用 `MemoryMigrateProfile` 提交 proposal 和读取时的全部 revision，说明每类事实的归属和冲突处理。工具先持久化目标及历史，再更新索引，最后归档旧画像；不手工先删源文件或入口。
5. 版本冲突就重新读取并合并；返回 pending migration 时使用 `resumeId` 恢复。恢复遇到新改动时用 `replanId` 保留所有当前编辑、恢复缺失的原来源并将旧计划退役为 `superseded.json` 历史；然后重新读取最新版本并语义合并。重规划本身不代表完成，不能为通过校验覆盖新内容。工具成功后再检查剩余来源，来源、未完成记录和 `migrationIssues` 都清空才声称迁移完成。异常来源不影响正常来源处理，不得跟随链接或绕过路径限制。旧目录包含画像或有迁移中断记录时，应用暂停目录搬移以保留源索引关系。以后新增的旧画像按相同步骤增量迁移。

## 日常更新、复查与过期

- 先 `MemoryInspect`，再用 `MemoryUpdate` 提交完整正文、revision 和实际依据 summary；全局用 `global-profile`，项目文件用文件名。写后核验，新主题/改名/归档必须同步索引；不为清除提醒伪造核验。
- 条目相邻记录来源（source）、范围（scope）、实际核验日期（verifiedAt）；有截止日期的临时事实记录 validUntil，超过有效期时先核验，不能继续作为当前事实。稳定偏好不会因一周未更新失效；用户纠正时及时修订。阶段性目标、项目状态超过一周结合本轮证据复查，长期决策保留适用条件和被替代关系。
- 运行时按文件版本和实际复查记录提醒超过一周的内容。读取不更新检查时间；实际核验后可用 `MemoryUpdate` 提交不变正文及依据，仅更新复查记录，不改变正文修改时间。文件级记录不代表每条事实刚刚核验，未检查的条目保留自己的日期和待核验状态。
- 已过期或被替代的整个非核心主题用 `MemoryArchive` 归档，同时提交去掉有效入口的新索引。归档保留原文；核心画像/项目偏好按条目更新，`MemoryUpdate` 会保存旧版全文供追溯。不能仅因文件旧就删除内容。
- 非画像的项目记忆主题混杂或超过上下文预算时，可按语义拆成项目主题并在项目索引保留路由；只整理本轮涉及的内容，不做无依据全库改写。尚待确认的事实必须显式标记，不能当作确定偏好。
