# 项目地图

在明确项目内开展工作时，项目 `AGENTS.md` 缺失、为空或不足 200 个非空白字符，都按尚未建立完整项目地图处理：主动建立或补全，无需单独的初始化授权。少字不代表已有规则无效，先保留其中有效要求，再按事实完善。计划模式、只读任务和用户禁止写入的要求仍优先。仅回答普通问题、打开页面不触发建档。

运行时会单独突出空文件，并显示短文件的实际非空白字符数。空文件在本轮项目任务收尾前按已核验事实建立；不足 200 字意味着描述可能明显不足，本轮必须核验并确定需要更新的内容。若现有内容已足够或证据不足以补充，说明判断，不为凑字数扩写。

## 位置与职责

- 使用运行时给出的当前项目地图路径。活动 worktree 的事实和规则写在该 worktree，不能锚定主仓库另写一份。
- 项目 `AGENTS.md` 保存项目约定、架构和目录入口、真实命令、验证方法、边界与关键文档索引。项目可能是代码、文档或研究目录，不强套软件工程模板。
- 创建或维护时，必须有明确的「记忆维护」项，链接运行时给出的项目 `MEMORY.md` 和全局 `user_profile.md`，说明主题索引同步、全局与项目偏好范围、证据更新及过期整理。已有长地图也必须检查此关联；使用 `MemoryInitialize` 可追加方案并建立必需记忆，保留原文。通用记忆区块不计入项目事实的 200 字门槛，不能用它代替真实项目描述。
- 项目规则唯一主入口是实际项目根的 `AGENTS.md`：直接创建的项目使用 `workspace-files/AGENTS.md`，本地文件夹项目使用所选目录，worktree 使用当前 checkout。UI、系统上下文和维护工具遵循同一路径；不要在 Proma 管理目录新建另一份 AGENTS.md。
- 用户现有的 `AGENTS.md`、`AGENTS.MD`、`CLAUDE.md` 与祖先规则继续由 Pi 原生发现。已有规则先读，避免重复或冲突；不自动改名、搬迁或覆盖用户项目中的旧文件。
- 同目录只有 `CLAUDE.md` 时，先核验其中规则；新建 `AGENTS.md` 必须保留指向它的明确入口，要求后续任务先读取并遵循，避免候选文件优先级变化使旧规则失效。保留原文件，不复制一份容易漂移的规则正文。

## 建立与更新

1. 使用 `ProjectMapInspect` 读取目标现有内容、状态和 `revision`，再读取本轮需要的相关规则。工具绑定当前项目或 worktree，无需自行传入路径。复用当前任务已核验的证据；必要时补读 manifest、真实脚本、测试配置、目录入口或项目文档，不只凭文件名猜测。
2. 缺失或内容不足时，在本轮结束前建立或补全有证据支持的项目地图。只写已经核实、对后续工作有用的内容；不为达到 200 字凑字数、填占位章节或编造命令。证据不足时保留已有内容，说明尚待完善。
3. 每轮项目任务收尾时，顺带检查本轮已确认的变化：项目当前阶段或里程碑、用户要求、关键文件新增/移动/删除、目录入口、运行与验证方式。有影响后续工作的变化就局部同步更新，不等待用户专门要求；无变化不重写，不另起全项目扫描或周期整理。阶段性状态注明日期，只保留对后续任务有用的概况，不写每轮流水账。保留用户内容，已有受管区块优先局部更新；有冲突时先说明，不强制追加通用协议。
4. 写入前重新核对目标是否已被其他会话创建或修改；出现新内容则先读再合并。写后回读验证，并在任务结果中简短说明。

## 超过一周的复查与检查记录

- 首次没有检查记录时，按文件修改时间判断；已有当前版本的检查记录时，取修改时间和检查时间中较新的一个，超过 7 天才提醒。时间久不等于规则失效：结合本轮任务核验是否仍然适用，必要时局部更新，无需全项目扫描。
- 实际完成核验后，调用 `ProjectMapReviewComplete`，传入 `ProjectMapInspect` 返回的 `revision`，并在 `summary` 中说明核验内容、依据和更新或无需更新的结论。若修改过文件，先再次调用 `ProjectMapInspect` 回读验证，再确认完成；若版本已变化，重新读取核验，不能确认旧版本。
- 检查记录由工具保存在 Proma 工作区元数据中，按项目/worktree 隔离。无需修改 `AGENTS.md` 的日期，也禁止用 `touch` 代替检查。没有内容变化时，文件正文和修改时间保持不变。
- 仅收到提醒、尚未实际核验或证据不足时，不得确认完成。计划模式、只读要求、用户禁止写入、普通问答和打开页面都不触发检查记录写入。
- 检查时间只控制一周复查提醒，不会消除空文件或不足 200 字的提示。文件内容或修改时间变化后，旧版本的检查记录不再适用。

架构、命令、入口等事实写在项目地图；用户偏好和可复用经验写 Memory；长篇调研和设计正文放项目 Context。没有变化不重复改写。

## 旧外层 AGENTS.md 的语义迁移

- 发现旧外层规则时，先用 `ProjectInstructionsInspect` 读取项目根文件、全部旧来源、版本和迁移状态。已有原文在迁移完成前继续加载，不能忽略外层有效要求。
- 根据证据逐项合并：保留双方有效规则，去重相同要求；冲突不按文件时间决定，有用户明确纠正时采用纠正后的规则，未解决的冲突先询问，解决前不提交。说明哪些要求保留、被替代以及依据。旧文件为空或相同时也要通过工具归档，不能留下会被原生祖先发现的副本。
- 提交 `ProjectInstructionsMigrate` 时带上目标与每份来源的原始版本、合并正文和依据。工具先保存来源与原目标的历史、写入并核验项目文件，最后归档外层文件；禁止先手动删除旧文件。写后检查项目 AGENTS.md 的记忆关联和事实内容。
- 如果显示未完成迁移，用 `ProjectInstructionsResume` 恢复；若检测到外部新改动，先核对变化，再用 `ProjectInstructionsReplan` 保留新内容并退回待合并状态，重新 Inspect 和语义合并。不能为满足旧版本校验回滚用户改动。只有工具成功且再次检查没有待迁移来源，才报告完成。
- worktree 会话不得将工作区级旧规则只迁入当前分支后删除公共来源，应在原项目主目录会话完成迁移。迁移前可照常执行当前任务；只读、计划、无人值守或用户禁止写入时，仅报告状态，不修改规则或归档。

## 一次性基础能力维护

- 运行时提示首次能力待完善时，普通问候也先用 ProjectInstructionsMaintain；无需让用户选择是否初始化。空白或缺失文件只建立真实基础说明，不编造项目结构、命令或画像。两个不同非空规则返回 needs-merge 后再 Inspect 和语义 Migrate。
- Maintain/Migrate/Resume 的 ready 结果已包含必需记忆建立、链接校验和持久完成记录，无需再读写同一批文件或调用周检工具消除提醒。只有工具实际成功后，最终回复顺带一句“这次也顺手完善了项目的 Agent 协作能力”。
- 完成记录与项目根及文件状态绑定；后续普通会话不重复初始化、迁移或宣布优化。旧规则重新出现、目标或必需记忆被删除、关联失效时可重新维护。正常业务知识更新与一周事实复查是独立流程，不重跑迁移。
